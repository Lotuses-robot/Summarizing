# 15 · 对外接口 v1 协议参考（给外部 agent / 脚本）

> 2026-11-10 立（D-139）。给「我自己的 agent 要读要写 summarizing」开的稳定接口。
> 与内部 `/api/*` 共用**同一批领域函数与 shared schema**——行为一致，只是鉴权方式不同。
>
> 本文是**协议参考**：每个端点的请求、响应、状态码、错误体。
> 快速上手看 §一 与 §十一 的例子，接之前先读 §二 的安全边界。

---

## 一、通用约定

### 1.1 基址

```
http://<host>:3001/api/v1
```

生产环境是 `https://sum.lotuses.cn/api/v1`（经 Caddy 终止 TLS）。

### 1.2 鉴权

每个请求都要带：

```http
Authorization: Bearer <接入令牌>
```

- 令牌 = **设置 → 账户卡**里的「接入令牌」（32 位小写 hex）。
- 与信源接入地址 `/hook/<令牌>/...` 里用的是**同一把**（用户 2026-11-10 定 A 方案）。
- 令牌只走 header，**不进 URL**：不落服务端日志与浏览器历史。
- 账户被停用 → v1 立刻不可用（每次请求都读账户状态）。

### 1.3 时间格式

**全部是北京墙钟字符串，不带时区标记**：

```
YYYY-MM-DDTHH:mm:ss     例：2026-11-10T16:17:44
```

- 服务端不接收 `Z` / `+08:00` 后缀（带了会在校验层被拒）。
- 这是**本地墙钟**，不是 UTC：`2026-11-10T09:00:00` 就是北京时间上午九点。
- 只有日期的场景可以省掉时间（`2026-11-10`），但事项的 `dueDate` 元素必须写全。

### 1.4 错误体

除 `204` 外，所有非 2xx 响应都是同一种形状：

```json
{ "error": "人话说明" }
```

参数校验失败时多带 `issues`（zod 的原始路径与原因，逐条）：

```json
{
  "error": "请求体不合法",
  "issues": [
    { "path": ["identity", "displayName"], "message": "identity 必须含非空 displayName 键" }
  ]
}
```

### 1.5 状态码

| 码 | 何时 |
|---|---|
| `200` | 读了 / 改了，成功 |
| `202` | 收下了，正在后台处理（投喂、重试） |
| `204` | 成功，但没有响应体（存疑库丢弃） |
| `400` | 请求体或查询参数不合法 |
| `401` | 令牌无效，或账户已停用 |
| `404` | 目标不存在（**也用于「属于别的账户」**——不泄露存在性） |
| `409` | 状态不允许（见各端点） |
| `413` | 请求体超过 **1 MiB**（Fastify 默认 `bodyLimit`）。注意这是**框架层**的拒绝，响应体不是 `{error}` 形状，`content` 超长的场景要自己截断或分批 |

⚠️ **请求体上限 1 MiB**：撞上时返回 413 而不是 400——它发生在业务校验之前。逐字保留大段原文的需求请自行分批投喂（每条批次独立消化，系统不要求一次给全）。

## 二、安全边界

v1 是**独立作用域**，路由清单只在一个文件里（`apps/server/src/routes/v1.ts`）。以下能力**永远不在** v1，访问一律 `404`：

| 不可达路径 | 原因 |
|---|---|
| `/api/v1/settings/ai` | 返回**明文 AI key** |
| `/api/v1/auth/source-token/rotate` | 能把你锁在门外 |
| `/api/v1/auth/password` | 同上 |
| `/api/v1/settings/rejection-rules` | 静默改变 agent0 的全部判类行为 |
| `/api/v1/sources/**` | 改白名单 = 改「哪些消息能进来」 |
| `/api/v1/backup` | 全库备份 |
| `/api/v1/chat` | 见 §十 |

⚠️ **一套令牌两用有代价**：把接入地址交给上游程序（如微信桥接），等于把 v1 的读写权也交给它。上游若打印配置或写崩溃转储，令牌会跟着流出去。要收紧的话是加一列 `apiToken`、设置页两把都显示——改动不大，但本轮按用户选择保持一把。

## 三、数据结构

下面这些形状在多个端点里复用。字段名与 `packages/shared/src/index.ts` 一致。

### 3.1 `Element` —— 事项的一个信息元素

```json
{ "label": "name", "text": "交高数作业", "note": null }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `label` | string | 元素名。固定三种：`name`（语义名，**恰好一个**）、`dueDate`、`summary`；其余是自由标签（`链接`、`地点`、`材料`…） |
| `text` | string | 内容。`dueDate` 的特殊之处：必须是完整墙钟 `YYYY-MM-DDTHH:mm:ss` |
| `note` | string \| null | 推断依据；非 null 表示「这个值是推出来的，不是原话里明写的」 |

### 3.2 `Item` —— 事项 / 通知

```json
{
  "id": "a1b2c3",
  "elements": [ { "label": "name", "text": "交高数作业", "note": null } ],
  "tags": ["高等数学"],
  "status": "todo",
  "kind": "task",
  "doubtNote": null
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 事项 id |
| `elements` | Element[] | 信息元素（`name` 恰好一个） |
| `tags` | string[] | 归类标签 |
| `status` | `todo` \| `done` \| `trashed` | 处置状态 |
| `kind` | `task` \| `notice` | 分类轴：事项 / 通知 |
| `doubtNote` | string \| null | 非 null = 存疑中（存量字段，新数据恒 null） |

### 3.3 `PageMeta` —— 分页信息

```json
{ "folded": false, "page": 1, "pageCount": 3, "total": 47 }
```

- `folded = true` 表示**这一次没有取行**（只给了计数），不是「这段是空的」。
- `total` 是**全量条数**，不是本页条数。
- 页码越界会被**夹到有效页**并在这里如实回报。

### 3.4 `RawInput` —— 一条进站批次

```json
{
  "id": "efd1d5cc-...",
  "content": "周五前交高数作业",
  "source": "agent",
  "identity": { "displayName": "我的 agent" },
  "receivedAt": "2026-11-10T16:17:44",
  "eventTime": null,
  "digestState": "digested"
}
```

| 字段 | 说明 |
|---|---|
| `content` | 原文，**逐字**，永不删除 |
| `source` | 信源短名（`chat` / `nc` / `wxweb` / 你自定的 `agent` …） |
| `identity` | 弹性字典，**必含非空 `displayName`**；可自由加键（`groupId`、`sender`…） |
| `receivedAt` | 落在服务端的时刻 |
| `eventTime` | 事情本身发生的时刻；`null` = 未知（**不会拿 receivedAt 兜底**） |
| `digestState` | `pending`（排队）/ `digesting`（消化中）/ `digested`（完成）/ `failed`（未处理） |

### 3.5 `ItemRow` —— 看板/通知里的一行

```json
{
  "item": { "...": "见 3.2" },
  "overdue": false,
  "dueDateInferred": false,
  "updatedAt": "2026-11-10T16:17:44",
  "completedAt": null,
  "viewed": false
}
```

| 字段 | 说明 |
|---|---|
| `overdue` | 渲染时派生：`ddl < 现在` 且 `status = todo` |
| `dueDateInferred` | `dueDate` 元素的 `note` 非 null（= 推出来的日期） |
| `updatedAt` | 最新版本的落库时刻 |
| `completedAt` | 最近一次进入已完成的时刻；非 done 为 null |
| `viewed` | 是否被打开过（「新」微标） |

## 四、读接口

### 4.1 `GET /api/v1/board`

看板三段 + 标签全集 + @ 候选。

**查询参数**

| 参数 | 默认 | 说明 |
|---|---|---|
| `page` | `1` | 已完成段的页码（1 起） |
| `folded` | `0` | `1` = 该段折叠，**服务端一个 done 行都不查**，只回条数 |

**响应 `200`**

```json
{
  "undated":   [ /* ItemRow[] 日期未知 */ ],
  "scheduled": [ /* ItemRow[] 已排期，按 ddl 升序 */ ],
  "done":      [ /* ItemRow[] 已完成，**只有当前页** */ ],
  "doneMeta":  { "folded": false, "page": 1, "pageCount": 3, "total": 47 },
  "tags":      ["高等数学", "英语"],
  "failedRawInputs": [ /* RawInput[] 「未处理」横幅 */ ]
}
```

- `tags` 是服务端按全量算的，不受分页影响。
- `folded=1` 时 `done` 是空数组，但 `doneMeta.total` 仍然准确。
- **没有** `mentionables`——@ 候选是独立端点，见 §4.13。

**错误**：`400`（`page` 非正整数，或 `folded` 不是 `0`/`1`）

```bash
curl -H "Authorization: Bearer $TOKEN" "$BASE/api/v1/board?folded=1"
```

### 4.2 `GET /api/v1/items/:id`

单条事项详情。

**响应 `200`**

```json
{
  "item": { "...": "Item" },
  "evidence": [
    {
      "id": "e1", "itemId": "a1b2c3", "subject": "元素:name",
      "fragmentId": "f1", "pointer": null,
      "capturedAt": "2026-11-10T16:17:44",
      "capturedBy": "agent0:deepseek-chat"
    }
  ],
  "fragments": [
    { "id": "f1", "content": "周五前交高数作业", "contentHash": "…", "rawInputId": "efd1d5cc-…" }
  ],
  "versions": [
    {
      "id": "v1", "itemId": "a1b2c3", "action": "create_item",
      "detail": "新建事项「交高数作业」",
      "snapshot": { "elements": [], "tags": [], "status": "todo", "kind": "task", "doubtNote": null },
      "at": "2026-11-10T16:17:44",
      "by": { "actor": "agent0", "model": "deepseek-chat" },
      "revokedBy": null
    }
  ],
  "rawInputs": { "efd1d5cc-…": { "...": "RawInput" } },
  "media": {
    "https://原始链接/a.png": { "id": "sha256…", "mime": "image/png", "sizeBytes": 91234, "expiresAt": "2026-12-10T…" }
  }
}
```

- `evidence[].subject` 一律是 `元素:<label>`——这条证据支撑的是哪个元素。
- `evidence[].capturedBy` 是**字符串** `actor:model`（无模型时只有 `actor`），不是对象。
- `versions[].by` 是**结构化对象** `{ actor, model }`（两者形状不同是历史原因，D-88）。
- `fragments` 是原文快照池，`rawInputs` 按批次 id 索引（引文悬浮窗的数据链）。
- `media` 的 key 是原文里 `[图片](url)` 的 url 原文；过期/未缓存的图不在表里。

**错误**：`404` 事项不存在（含属于别的账户）

### 4.9 `GET /api/v1/search`

全文检索**历史原文批次**（不是事项——事项用 4.3）。

**查询参数**（都可选，可组合）

| 参数 | 说明 |
|---|---|
| `query` | 关键词（切词后模糊匹配内容与身份） |
| `source` | 信源种类（`nc` / `chat` / `agent`…）或身份显示名 |
| `identity` | **键值对数组的 JSON 串**，如 `[{"key":"groupId","value":"12345"}]`；精确匹配 |
| `after` / `before` | 时间上/下界（墙钟） |
| `mode` | `all`（交集，默认）/ `any`（并集） |
| `limit` | 1~50；**越界直接 400**，不静默改写 |

**响应 `200`**

```json
{
  "hits": [
    {
      "id": "efd1d5cc-…",
      "content": "周五前交高数作业",
      "truncated": false,
      "contentLength": 8,
      "source": "agent",
      "identity": { "displayName": "我的 agent" },
      "receivedAt": "2026-11-10T16:17:44",
      "eventTime": null
    }
  ],
  "total": 1,
  "more": 0
}
```

- `truncated = true` 时 `content` 被截断，`contentLength` 是**原文真实长度**。
- `total` 不受 `limit` 影响；`more` = 命中但没返回的条数。
- 单次结果总量有 2,000 字预算——装不下的**单条**会被跳过（不是整体截断），`more` 会反映这一点。

**错误**
- `400` 参数不合法（含 `limit` 越界、`identity` 不是合法 JSON 数组）

```bash
curl -H "Authorization: Bearer $TOKEN" \
  "$BASE/api/v1/search?query=%E5%86%99%E4%BD%9C&mode=any&limit=10"
```

### 4.11 `GET /api/v1/usage?range=<today|7d|30d>`

token 用量。缺省 `7d`。口径 = **北京墙钟的日历日**（含今日）。

**响应 `200`**

```json
{
  "range": "today",
  "inputTokens": 12000,
  "completionTokens": 3400,
  "cachedTokens": 8800,
  "callCount": 5
}
```

- 三个 token 数**互不重叠**：`inputTokens` 是未命中部分（已减掉缓存命中），
  `inputTokens + cachedTokens + completionTokens = 实际总消耗`。
- `cachedTokens` 为 `null` ⇔ 区间内所有调用都没返回缓存字段（服务商不提供）——**与「命中 0」不同义**。
- `callCount` 区分「零调用」与「调用了但零用量」。

**错误**：`400` `range` 不是三个枚举之一

---

### 4.12 `GET /api/v1/media/:id`

取图片字节。图片是**证据链的一环**——事项正文与引文里的 `[图片](url)` 占位要靠它渲染成图。

- `id` = 内容寻址的 sha256（`GetItemResult.media` 的 key 对应的值里就有）
- 只读：**不提供上传口**（`POST /api/v1/media` 返回 404）
- 与浏览器端点的实现是同一份（`registerMediaReadRoute`），行为不会分叉

**响应 `200`** —— 二进制，`Content-Type` 为实际图片 MIME，头带 `Cache-Control: private, max-age=31536000, immutable`。

**错误**
- `401` 未带令牌
- `404` 图片不存在 / 文件已过期清理（两者同形，不泄露存在性）

```bash
curl -H "Authorization: Bearer $TOKEN" -o pic.png "$BASE/api/v1/media/<sha256>"
```

### 4.13 `GET /api/v1/mentionables?q=`

**@ 提及候选**：非回收站的**全部条目**（事项 + 通知），按最近更新倒序，上限 500 条。

用途：用户说「把**它**改成周三」时，给「它」一个候选池做消歧。不需要时可以不调——看板响应里不再带它。

**查询参数**

| 参数 | 默认 | 说明 |
|---|---|---|
| `q` | 空 | 前缀/子串过滤；空串 = 不过滤 |

**响应 `200`**

```json
{
  "items": [
    { "id": "a1b2c3", "title": "交高数作业" },
    { "id": "d4e5f6", "title": "数据结构课改到明理楼3楼" }
  ],
  "total": 53
}
```

- `total` 是**过滤后的池子大小**（可能大于 `items.length`——超出 500 的部分没下发）。
- 为什么与看板分开：看板被 `kind=task` 与分页折叠切过——拿看板行当候选，**折叠时一条已完成都 @ 不到**，通知更是整个不在看板里。候选要的是全量口径。

**错误**：`400`（`q` 不是字符串）

```bash
curl -H "Authorization: Bearer $TOKEN" "$BASE/api/v1/mentionables?q=作业"
```

## 五、写接口

### 5.1 `POST /api/v1/ingest`

投喂一条信息进管线：**先落盘、后异步消化**。与信源、粘贴走同一条路。

**请求体**

```json
{
  "content": "周五前交高数作业",
  "source": "agent",
  "identity": { "displayName": "我的 agent" },
  "eventTime": null
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `content` | ✅ | 原始文本，**逐字**——不要改写或摘要（下游要拿原文核对引文） |
| `source` | ✅ | 信源短名，会显示在界面与流水里 |
| `identity` | ✅ | 弹性字典，**必须含非空 `displayName`** |
| `eventTime` | ❌ | 事情发生的时刻；省略 = `null`（未知）。**不要拿当前时间填**——那会让相对日期算错 |

**响应 `202`**

```json
{ "id": "efd1d5cc-…", "digestState": "digesting" }
```

`digestState` 是**置位结果**，不是发起前的快照。

**错误**：`400` 缺字段 / `identity` 没有 `displayName`

> ⚠️ 经 v1 投喂的批次**不带对话上下文**（它不是从对话来的）。要在 `content` 里写清背景。

```bash
curl -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"content":"周五前交高数作业","source":"agent","identity":{"displayName":"我的 agent"}}' \
  "$BASE/api/v1/ingest"
```

> 💡 **Windows Git Bash 提示**：中文 body 用 `-d` 内联时 curl 的 Content-Length 会按字节数算错，
> 报 `FST_ERR_CTP_INVALID_CONTENT_LENGTH`。把 JSON 写进文件用 `--data-binary @file.json`。

---

### 5.2 `POST /api/v1/items/:id/complete`

标完成（`status → done`）。

**响应 `200`** —— 更新后的 `Item`

**错误**
- `404` 事项不存在
- `409` 这条在回收站（先 `restore`）
- `409` 这是通知（`kind = notice` 没有完成状态）

---

### 5.3 `POST /api/v1/items/:id/reopen`

恢复待办（`status → todo`）。与 `complete` 对称。

**响应 `200`** —— 更新后的 `Item`

**错误**：同上（`404` / 回收站 `409` / 通知 `409`）

---

### 5.4 `POST /api/v1/items/:id/trash`

进回收站（`status → trashed`）。**幂等**——已在回收站则原样返回，不追加无意义版本。

**响应 `200`** —— 更新后的 `Item`

**错误**：`404` 事项不存在

---

### 5.5 `POST /api/v1/items/:id/restore`

从回收站恢复，回到**删前状态**（`done` 或 `todo`）。幂等——不在回收站则原样返回。

**响应 `200`** —— 更新后的 `Item`

**错误**
- `404` 事项不存在
- `409` 删前状态不可考（版本链异常，**不编造 `todo`**）

---

### 5.6 `POST /api/v1/raw/:id/retry`

重试「未处理」（`digestState = failed`）的批次。

**响应 `202`**

```json
{ "id": "efd1d5cc-…", "digestState": "digesting" }
```

**错误**
- `404` 批次不存在
- `409` 不是 `failed`（只有未处理的能重试）

---

### 5.7 `PUT /api/v1/uncertain/:id`

把存疑库里的条目**丢弃**（`status → discarded`）。只支持丢弃——**不支持 `merged`**（那要求调用方知道合并到哪条，等于替 AI 做判断）。

**响应 `204`**（无响应体）

**错误**
- `404` 条目不存在
- `409` 条目已被处置（并发不复活）

## 六、状态机

### 6.1 事项 `status`

```
                 ┌──── complete ────┐
                 │                  ▼
  创建 ──────► todo ◄── reopen ── done
                 │                  │
                 │      trash       │
                 └──────┬───────────┘
                        ▼
                     trashed ──restore──► 回到删前状态
```

- `trashed` 不是「第三种状态」，是**同一个状态的删除态**——恢复时回到删之前是什么（`todo` 或 `done`）。
- 通知（`kind = notice`）恒 `todo`，不参与完成演化；`complete`/`reopen` 会 `409`。

### 6.2 批次 `digestState`

```
ingest ──► pending ──► digesting ──► digested
                          │
                          └────────► failed ──retry──► digesting
```

- `failed` = **原文仍在**，只是没消化成功；可以反复 `retry`。
- 重启时被打断的批次会自动重试一次（只救一次，防重启循环）。

## 七、写路径的共同保证

不论走 v1 还是走界面，写操作都遵守同一组规矩：

| 保证 | 含义 |
|---|---|
| **版本链** | 每次改动追加一个版本节点，不覆盖历史——`GET /items/:id` 的 `versions` 能看到全部改动 |
| **`by` 署名** | v1 写入的署名是 `{ "actor": "外部接口", "model": null }`；界面上能区分「谁改的」 |
| **回收站不是物理删** | `trash` 只改状态；彻底删只发生在「一键清理 >15d」（**v1 不提供**） |
| **原文永不删** | 无论事项怎么改怎么删，进站批次（`raw_inputs`）永远保留 |
| **`source` 由你定** | 用自定的短名（如 `agent`），界面上「来源」会显示这个名字 |

## 八、与界面/前台的边界

### 8.1 v1 **不提供**前台对话

`POST /api/v1/chat` 刻意缺席。

理由：它与 v1 的读写面功能重叠，但把「你的 agent」和「前台」两个智能体叠在一起——出错时你分不清是谁判错了；而且它慢（多轮工具循环）、贵（每轮一次模型调用）、还会写进你的对话历史。

需要「让前台帮忙看板/收录」的场景，自己编排：

```
GET  /api/v1/board     → 取现状
POST /api/v1/ingest    → 投喂新信息（agent0 在后台消化）
```

### 8.2 对话上下文只属于对话入口

经 v1 投喂的批次 `context` 为空。前台对话录入的批次会带**最近 6 轮对话 + @ 提及**给 agent0 做指代消解——那是对话入口专属的能力。

## 九、限流与容量

- v1 **没有**请求限流（限速只挂在登录/注册端点，防密码爆破）。
- 但底层有真实上限：
  - **请求体 ≤ 1 MiB**（框架层，超了返回 413）
  - `search` 的单次结果总量 2,000 字、`limit` ≤ 50
  - `pipeline/runs` 的 `limit` ≤ 200
  - `ingest` 的上下文上限：6 轮 / 单轮 500 字（超出截断并注明原长度）
  - 图片读回单张 ≤ 500 KiB（上传时已压缩；v1 只读不给上传口）

自建脚本请自行节流，不要拿它做高频轮询。

## 十一、完整示例

```bash
export TOKEN=<你的接入令牌>
export BASE=http://localhost:3001

# ── 读：现在的日程 ──
curl -s -H "Authorization: Bearer $TOKEN" "$BASE/api/v1/board" \
  | jq '(.undated + .scheduled)[] | {
      name: (.item.elements[] | select(.label=="name") | .text),
      due:  ((.item.elements[] | select(.label=="dueDate") | .text) // "无"),
      overdue
    }'

# ── 读：已完成第 1 页 ──
curl -s -H "Authorization: Bearer $TOKEN" "$BASE/api/v1/board?page=1" | jq '.doneMeta'

# ── 写：投喂一条新信息 ──
cat > /tmp/ingest.json <<'JSON'
{"content":"周五前交高数作业","source":"agent","identity":{"displayName":"我的 agent"}}
JSON
BATCH=$(curl -s -X POST -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" --data-binary @/tmp/ingest.json \
  "$BASE/api/v1/ingest" | jq -r .id)

# ── 等消化完（真实场景请轮询 pipeline/runs）──
sleep 10
curl -s -H "Authorization: Bearer $TOKEN" "$BASE/api/v1/pipeline/runs/$BATCH" \
  | jq '{state: .raw.digestState, events: (.events | length)}'

# ── 写：把它标完成 ──
ITEM=$(curl -s -H "Authorization: Bearer $TOKEN" \
  "$BASE/api/v1/items/search?query=%E9%AB%98%E6%95%B0" | jq -r '.items[0].id')
curl -s -X POST -H "Authorization: Bearer $TOKEN" "$BASE/api/v1/items/$ITEM/complete" | jq .status

# ── 写：后悔了，删掉 ──
curl -s -X POST -H "Authorization: Bearer $TOKEN" "$BASE/api/v1/items/$ITEM/trash" | jq .status

# ── 写：从回收站捞回来 ──
curl -s -X POST -H "Authorization: Bearer $TOKEN" "$BASE/api/v1/items/$ITEM/restore" | jq .status
```
