# 信源阶段可行性测试计划（04§五 验收；2026-09-28）

> 目标（唯一硬指标）：**接入一个新信源 ≤ 30 分钟**（04§五 / archive/06-信源阶段.md §一）。
> 判据不是「能不能跑通」，而是**「哪个环节在吃时间」**——超时暴露的是**宿主设计缺陷**，比做完整个机器人再发现便宜。
> 尺子：docs/07-接新源检查单（chat 源为参照实现）。

## 一、测试对象与基线

| | nc 源（本次实测） | chat 源（参照基线） |
|---|---|---|
| 入口 | HTTP WebHook 回调 | 对话输入 / POST /api/ingest |
| 元数据 | `{name:群名, groupId, sender}` | `{name:"用户对话"}` |
| 打包 | 内存缓冲 + 去抖封批 | 无（一条一批） |
| 适配器代码量 | `sources/nc/` 约 190 行（含注释） | 0（复用共享管线） |

**基线观察**：nc 是**回调型 + 需打包**的源，比 chat（单发、无打包）复杂——它是「较难的样板」，测它有代表性。

## 二、掐表方法（关键：分解计时）

**总时长 = 接一个新源从零到全链路跑通**。分解成 5 个环节分别计时，超时才能定位根因：

| 环节 | 计时起点 | 计时终点 | 达标参考 |
|---|---|---|---|
| T1 读检查单 | 打开 docs/07 | 明确「入口/元数据/打包/推理/验证」五问答案 | ≤ 5 min |
| T2 写适配器 | 建 `sources/<name>/` 目录 | 适配器 `register` 能挂路由 + 收到 204 | ≤ 12 min |
| T3 元数据配置 | 决定 sourceIdentity 结构 | 写入信源设置（白名单） | ≤ 3 min |
| T4 端到端验证 | 发第一条真实事件 | 看板出现/并入正确事项 | ≤ 8 min |
| T5 排障（若有） | 发现问题 | 定位并解决 | 计入，暴露痛点 |

> ⚠️ **不计入**：nc 端的一次性环境安装（下载/登录 QQ/装 nc 插件）——那是**信源自身的部署成本**，不是「接进本系统」的成本。计时从「nc 已能正常收发消息」开始。

## 三、测试步骤（真实操作，不模拟）

### 阶段 A：清场（准备工作，不计时）
1. 停所有 dev 进程，**单进程非 watch 模式**起 server（`cd apps/server && npm start`）——避免热重载清空内存缓冲
2. 清空测试遗留：删掉我联调时的测试白名单项、清掉测试批次与事项
3. **备份真库**（`data/backup/`，防测试污染）

### 阶段 B：掐表实测「接一个新源」（T1–T4）

**以「接一个全新源」的视角走一遍**（哪怕代码已在——测的是**流程是否顺畅**）：

- **T1**：只读 `docs/07`，看能否在 5 分钟内答出五问、知道该动哪些文件（不看已有 nc 代码）
- **T2**：照检查单建目录、写适配器。**观察点**：有没有「检查单没写的隐含知识」逼你去翻别的文件/问人
- **T3**：`SystemContext` 设置接口好不好用、有没有不知道该填什么
- **T4**：发真实消息 → 看板。**观察点**：失败时的报错够不够让你自己定位

### 阶段 C：存疑信息库全链路（D-85，本次新增能力）

1. 发一条**拿不准**的消息（如「好像还有个材料清单要交」）→ 观察：是否进存疑库而非建事项
2. `GET /api/uncertain` 查 → 条目在、needsHuman 与理由可读
3. 发一条**补全上下文**的消息 → 观察：agent0 是否检索到库、合并升格（条目转 merged）
4. 对话说「清扫存疑库」→ 观察：清扫循环跑通、结果可读

### 阶段 E：边界与失败模式

| 场景 | 期望 |
|---|---|
| 白名单外群消息 | 204 静默丢，不落档 ✅（已验） |
| 私聊消息 | 204 静默丢 ✅（已验） |

## 四、退出判据

- **达标**：T1–T4 合计 ≤ 30 min，全链路正确，无「检查单没写的隐含知识」
- **暴露缺陷**（同样算有价值）：超时，且能定位到具体环节 → 记录为**宿主设计缺陷**，提改进项
- **不通过**：链路有断点、数据丢失、或需要改 core 才能接新源（违反低耦合红线）

## 五、已知的环境陷阱（测试时避开）

1. **`tsx watch` 热重载清空内存缓冲** —— 测试期**不改代码**；用 `npm start`（非 watch）
2. **多套 dev 进程抢 3001** —— 开测前确认只有一个进程监听
3. **nc 的 `ws-default` 废配置** 会反复报 `EADDRINUSE 3001` —— 建议删掉，免得干扰判断
4. **窗长默认 3 分钟** —— 想快速看到结果就调短（`PUT /api/sources/nc/settings/windowMinutes`，最小有效值 1）
5. **bash 多行 python 被转义咬** —— 排查脚本写成文件跑，不就地 heredoc
