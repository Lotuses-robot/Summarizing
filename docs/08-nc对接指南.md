# 08 · nc 对接指南（只读信源，D-84；2026-10-11 起接入地址含账户令牌）

> **本文件 = 把 nc 接到本系统的操作说明**。上游：06§三（06-信源阶段.md；archive 已移出仓库——位置见 CLAUDE.md 文档地图）、D-84。
> 只读：不发消息、不代操作——nc 把群消息推给我们，我们只收。
> ⚠️ 多用户批次（006）起，上报地址 = `/hook/<你的接入令牌>/nc/event`（网关统一鉴权；无/错令牌 401 且不落任何库）。

## 一、原理

```
QQ 群/私聊消息 ──nc HTTP WebHook──▶ POST /hook/<你的接入令牌>/nc/event
                                     ├─ 令牌鉴权（错/停用 → 401，零落库）
                                     ├─ 白名单过滤（群白名单 / 私聊白名单；名单外 204 丢弃并留痕）
                                     ├─ 消息 id 去重（重推幂等）
                                     └─ 入内存缓冲（按会话分组）→ 204 快收
   ▼（四个切段条件任一命中：静默满窗 / 攒够条数 / 攒够字节 / 距首条超时）
   合并成一批 → 落档 raw_inputs → agent0 消化 → 看板
```

- **同一会话连续发的多条消息合并成一个批次**（碎片打包，06-信源阶段.md §3.3；archive 已移出仓库）——群里【1/2】【2/2】两条通知进站就是一批。
- **批次有上界，不会无限攒**（D-127 三闸 + 龄期闸）——忙群一直有人说话时，原来「静默 3 分钟」永远不成立，批次会一直涨；现在四个条件任一命中就切段。默认值与含义见 §三。
- **私聊也收**（2026-10-13 起）：在「设置 → 信源 → 私聊白名单」填对方 QQ 号 + 备注名；未配置 = 私聊全不收（fail-closed）。
- **事件时间用消息自带时刻**（比到达时刻真实）；两者差距本身是信息。
- **令牌**：每个账户一把、管名下所有信源；服务端日志对令牌脱敏。

## 二、拿到你的接入地址

登录后打开 **设置 → 信源** 区，nc 卡片顶部的「**接入地址**」框即是（点复制）：

- 本机自用：`http://127.0.0.1:3001/hook/<你的接入令牌>/nc/event`
- 局域网/手机：`http://<电脑局域网IP>:3001/hook/<你的接入令牌>/nc/event`（server 已监听 `0.0.0.0`）
- 上线后：`https://sum.lotuses.cn/hook/<你的接入令牌>/nc/event`

> 泄露（截图/误发）时的对策：同处点「**重新生成接入令牌**」——旧地址即刻失效，用新地址更新 nc 配置即可。

## 三、nc 侧配置

1. nc 启动后进 WebUI → **网络配置** → 新增 **HTTP 服务器**（不要选 SSE）。
2. 配置：
   - **主机**：`0.0.0.0`（或留默认）
   - **端口**：任意未占用端口（如 `3000`；不要与我们的 3001 撞）
   - **消息格式**：`array`（推荐——图片段能识别）或 `string`
   - **启用「反向 WebSocket / HTTP 上报」**：指向**第二节复制的接入地址**
3. 勾选要上报的事件类型：**群消息**（group message）——要在设置里配了群白名单才收；私聊想收就一并勾私聊事件，并在设置里配私聊白名单（未配置则一律 204 丢）。

> ⚠️ nc 与本地系统在同一台机器时用 `127.0.0.1`；nc 装在别处（如另一台机器/容器）用其可达的局域网 IP。

## 四、配置白名单（必做，否则一律丢弃）

**采集范围 = 群白名单 + 私聊白名单，默认空 = 全丢**（fail-closed，D-84 Q-F）。**优先走设置界面**：设置 → 信源 → nc——groups 行加「群号: 备注名」、privates 行加「对方QQ号: 备注名」、windowMinutes 行改窗长，改完即存即生效。

curl 备选（**需带登录会话 cookie**——浏览器登录后从开发者工具复制 `sid`；嫌麻烦就直接只用界面）：

```bash
# 白名单：{"群号": "群备注名"}（备注名进 identity.displayName，供 agent0 判断权威性）
curl -b "sid=<你的会话cookie>" -X PUT http://localhost:3001/api/sources/nc/settings/groups \
  -H "Content-Type: application/json" \
  -d '{"123456789": "英语课官方群", "987654321": "数据结构班群"}'

# 切段条件（四个，各自可调；改即生效不重启）
#   windowMinutes  静默切段：同一会话静默这么久就封批（默认 3 分钟）
#   maxEvents      最多条数：一个批次最多攒这么多条（默认 50）
#   maxBytes       最多字节：一个批次正文累计到这么大就切（默认 20480）
#   maxAgeMinutes  最长跨度：从批内首条消息起最多跨这么久（默认 10 分钟）
curl -b "sid=<你的会话cookie>" -X PUT http://localhost:3001/api/sources/nc/settings/windowMinutes \
  -H "Content-Type: application/json" -d '3'

# 查看当前设置
curl -b "sid=<你的会话cookie>" http://localhost:3001/api/sources/nc/settings
```

群号在 QQ 群设置里能看到（或 nc 日志里上报的 `group_id`）。

## 五、验证

1. 在已加入白名单的群里发两条消息（如「作业通知」「截止10月8日」）。
2. 等切段——默认静默 3 分钟，或攒够 50 条 / 20KB / 跨满 10 分钟（以先到者为准）——看板应出现合并后的一个事项。
3. 点开事项 → 「原始信息」可溯源到那两条消息的原文。
4. 排查：
   - 没反应 → 检查白名单是否包含该群号；nc 上报地址是否用了**完整接入地址（含 /hook/<令牌>/）**。
   - 群里/私聊发了没进 → 白名单外不收（设计行为，204 静默丢）——**未收录的群/私聊会在服务端日志留痕一次**（`[source:nc] warn` 含会话键），可据此对照修正白名单。
   - 401 → 令牌错/账户停用/旧令牌已轮换——去设置里复制当前接入地址。
   - 想看有没有收到 → 设置界面确认配置；服务端日志 `[source:nc]` 前缀有封批日志（日志中令牌已脱敏为 `/hook/***/`）。

## 六、边界与已知限制

- **崩溃丢失有上界**：进程意外死掉时，最多丢掉「尚未切段的那一段」——它的上界是四个切段条件里最先到的那个（默认：静默 3 分钟 / 50 条 / 20KB / 10 分钟跨度）。连续刷屏的忙群尤其要看**最长跨度 10 分钟**这一条：只要群一直在说话，静默条件就永不成立，此时丢失上界由它决定（旧文档这里写的「≤3 分钟」在连续聊天时是错的，2026-10-22 订正）。消息仍在 QQ 群里，可手动补。进程 `Ctrl-C`（SIGINT）会尽力强制封批全部组（尽量不丢）。
- **图片**：转 `[图片](url)` 占位进 content（base64 不进库）；服务端在落档后**后台缓存**这张图（009）——原文一字不改，界面按映射渲染成图；原事件完整留底在批次 raw 归档列（将来要读引用/转发关系不必翻旧账）。
- **只读**：不回复、不点赞、不代任何操作。
- **接入地址含令牌**：别外发/截图晒配置；泄露就去设置里一键轮换。
- 期长/白名单改动即时生效，无需重启（下次事件/下次扫描读到新值）。
