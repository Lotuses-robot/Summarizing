# 08 · nc 对接指南（只读信源，D-84）

> **本文件 = 把 nc 接到本系统的操作说明**。上游：06§三（已在 archive/06-信源阶段.md）、D-84。
> 只读：不发消息、不代操作——nc 把群消息推给我们，我们只收。

## 一、原理

```
QQ 群消息 ──nc HTTP WebHook──▶ POST /api/sources/nc/event
                                     ├─ 白名单过滤（外群/私聊 204 丢弃）
                                     ├─ 消息 id 去重（重推幂等）
                                     └─ 入内存缓冲（按群分组）→ 204 快收
   ▼（组内静默满窗，默认 3 分钟）
   合并成一批 → 落档 raw_inputs → agent0 消化 → 看板
```

- **同一群连续发的多条消息合并成一个批次**（碎片打包，archive/06-信源阶段.md §3.3）——群里【1/2】【2/2】两条通知进站就是一批。
- **事件时间用消息自带时刻**（比到达时刻真实）；两者差距本身是信息。

## 二、nc 侧配置

1. nc 启动后进 WebUI → **网络配置** → 新增 **HTTP 服务器**（不要选 SSE）。
2. 配置：
   - **主机**：`0.0.0.0`（或留默认）
   - **端口**：任意未占用端口（如 `3000`；不要与我们的 3001 撞）
   - **消息格式**：`array`（推荐——图片段能识别）或 `string`
   - **启用「反向 WebSocket / HTTP 上报」**：指向 `http://<本机IP>:3001/api/sources/nc/event`
     - 本机自用：`http://127.0.0.1:3001/api/sources/nc/event`
     - 局域网/手机：`http://<电脑局域网IP>:3001/api/sources/nc/event`（server 已监听 `0.0.0.0`）
3. 勾选要上报的事件类型：**群消息**（group message）。私聊、通知类不必勾（勾了也会被我们 204 丢）。

> ⚠️ nc 与本地系统在同一台机器时用 `127.0.0.1`；nc 装在别处（如另一台机器/容器）用其可达的局域网 IP。

## 三、配置群白名单（必做，否则一律丢弃）

**采集范围 = 群白名单，默认空 = 全丢**（fail-closed，D-84 Q-F）。联调期用设置接口写入（设置界面随前端批次，本期未实现）：

```bash
# 白名单：{"群号": "群备注名"}（备注名进 sourceIdentity.name，供 agent0 判断权威性）
curl -X PUT http://localhost:3001/api/sources/nc/settings/groups \
  -H "Content-Type: application/json" \
  -d '{"123456789": "英语课官方群", "987654321": "数据结构班群"}'

# 打包窗长（分钟，默认 3；改即生效不重启）
curl -X PUT http://localhost:3001/api/sources/nc/settings/windowMinutes \
  -H "Content-Type: application/json" -d '3'

# 查看当前设置
curl http://localhost:3001/api/sources/nc/settings
```

群号在 QQ 群设置里能看到（或 nc 日志里上报的 `group_id`）。

## 四、验证

1. 在已加入白名单的群里发两条消息（如「作业通知」「截止10月8日」）。
2. 等一个窗口（默认 3 分钟）静默后——看板应出现合并后的一个事项。
3. 点开事项 → 「原始信息」可溯源到那两条消息的原文。
4. 排查：
   - 没反应 → 检查白名单是否包含该群号；nc 上报地址是否正确。
   - 群里发了没进 → 私聊不收、白名单外不收（都是设计行为，204 静默丢）。
   - 想看有没有收到 → `curl http://localhost:3001/api/sources/nc/settings` 确认配置；服务端 stderr 里 `[sources:nc]` 前缀有封批日志。

## 五、边界与已知限制

- **崩溃丢最近一个窗口**（≤3 分钟）的自动收取——消息仍在 QQ 群里，可手动补。进程 `Ctrl-C`（SIGINT）会尽力强制封批全部组（尽量不丢）。
- **图片**：转 `[图片](url)` 占位进 content（base64 不进库）；原事件完整留底在批次 raw 归档列（将来要读引用/转发关系不必翻旧账）。
- **只读**：不回复、不点赞、不代任何操作。
- 期长/白名单改动即时生效，无需重启（下次事件/下次扫描读到新值）。
