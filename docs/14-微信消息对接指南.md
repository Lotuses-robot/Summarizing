# 14 · 微信消息对接指南（wxweb 信源）

> **性质**：上游协议的**原文**（对方写给我们的），加上本仓的接入说明。
> 协议原文从「微信消息上报接口文档」起，**逐字保留**——上游改协议时以其为准。
> 本仓实现：`apps/server/src/sources/wxweb/`。

## 我们这边怎么接的（读这一节就够）

- **信源名**：`wxweb`（设置 → 信源 → 「微信消息」）。
- **接入地址**：设置页那张卡上的地址（`/hook/<令牌>/wxweb/event`）。填进上游看板即可。
- **白名单**：设置里的「会话白名单」，键 = `wx.conv_id` 原文（群 `<数字>@chatroom`、私聊对方 wxid）。
  **未配置 = 全都不收**（fail-closed，与 nc 同语义）。
- **自身消息**：按 `wx.is_self` 丢弃——**不比对 `user_id == self_id`**（微信里同一账号有带/不带后缀两种写法）。
- **去重**：按 `message_id`（上游明确要求接收侧做，见协议第 6 节）。
- **切段**：与 nc 同一套四闸（静默 / 条数 / 字节 / 龄期），设置里两个时间阀可调。
- **非文本消息**：上游只给占位文本（`[图片]` 等），我们原样保留，**不猜内容**。
- **引用回复**：正文前置「（回复 X）」；`reply` 段的 id 是本条自己的 local_id，不作为引用关系使用。
- **签名**：未接（`X-WX-Signature`）。当前靠地址里的账户令牌鉴权；上游若配置密钥，我们再补校验。

# 微信消息上报接口文档（Webhook）

> 面向接收方（sum.lotuses.cn）开发者。
> 本文描述**我方（macOS 本地服务）主动 POST 给你的消息事件**，以及可选的反向查询接口。
> 消息格式兼容 **OneBot 11**（与 NapCat 上报的 `message` 事件一致），
> 你现有的 OneBot / NapCat 解析器可以直接复用。

---

## 0. 概览

| 项目 | 说明 |
|---|---|
| 方向 | 我方 → 你的站点，**出站 HTTP POST**（webhook） |
| 触发 | 每捕获到一条新微信消息，立即 POST 一次（不做批量合并） |
| 协议 | HTTP/1.1，`POST`，`Content-Type: application/json; charset=utf-8` |
| 包体 | OneBot 11 消息事件 JSON，UTF-8，**不做 URL 编码** |
| 超时 | 12 秒 |
| 实测 | 我方已成功推送到 `https://sum.lotuses.cn/hook/<令牌>/nc/event`，收到 **204** |

消息来源：直读微信本地数据库（SQLCipher 解密），**不依赖系统通知**，
因此免打扰 / 静音会话的消息同样能收到。

---

## 1. 接线方式

1. 你的站点给我一个带令牌的 HTTPS 地址，形如
   `https://sum.lotuses.cn/hook/<令牌>/nc/event`
2. 我把这条地址填进本机看板配置，点「发送测试」
3. 你收到一条 `content` 为「这是一条测试消息，来自 wxweb 的「发送测试」」的事件，即握手成功

地址变更（令牌轮换）时，我改配置即可，无需你侧改动。

---

## 2. 请求规范

### 2.1 请求头

```
POST /hook/<令牌>/nc/event HTTP/1.1
Host: sum.lotuses.cn
Content-Type: application/json; charset=utf-8
User-Agent: wxweb/1.0
X-WX-Event: message
X-WX-Signature: sha256=<hex>          # 仅当配置了签名密钥时携带
```

| 头 | 必带 | 说明 |
|---|---|---|
| `Content-Type` | ✅ | 固定 `application/json; charset=utf-8` |
| `X-WX-Event` | ✅ | 当前恒为 `message`。未来若扩展事件类型会在此区分 |
| `X-WX-Signature` | ❌ | 签名，见第 8 节。未配置密钥则不带 |

### 2.2 请求体

单个 JSON 对象，**不是数组**，每次一条消息。

---

## 3. 响应约定与重试策略

**你只要返回 2xx 就算成功。** 请求体不需要任何内容，**空响应体（204）完全正常**。

建议：**收到后立刻返回 2xx，把入库、AI 处理等重活丢到异步队列**。
如果在请求线程里做重活导致超时，我方会重试，造成重复投递。

我方按响应码分类处理：

| 你的响应 | 我方行为 |
|---|---|
| `2xx`（含 200 / 201 / 204） | 成功，结束 |
| `429` | 退避重试，最多 4 次（间隔 2 → 4 → 8 → 8 秒），仍失败则落盘 `outbox` |
| `5xx` | 同上，退避重试 4 次后落盘 |
| 网络错误 / 连接超时 | 同上，退避重试 4 次后落盘 |
| 其他 `4xx`（400/401/403/404…） | **不重试**，直接落盘 `outbox`（判定为地址或令牌配错，重试无意义） |

落盘的消息存在本地 `data/webhook_outbox.jsonl`，不会丢，可事后重放。

## 4. 事件格式

### 4.1 顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `time` | int | 消息时间，Unix 秒 |
| `self_id` | string | 被监控账号自己的 wxid，如 `wxid_1p4nyyjk5ztn19_0e21` |
| `post_type` | string | 恒为 `"message"` |
| `message_type` | string | `"group"` 群消息 / `"private"` 私聊 |
| `sub_type` | string | 恒为 `"normal"` |
| `message_id` | string | **幂等键**，格式 `<conv_id>_<local_id>` |
| `user_id` | string | 发送人 wxid |
| `message` | array | OneBot 消息段数组，见 4.5 |
| `raw_message` | string | 纯文本形式的消息内容 |
| `font` | int | 恒为 `0` |
| `sender` | object | 发送人信息，见 4.6 |
| `group_id` | string | 仅群消息有，形如 `49962529981@chatroom` |
| `anonymous` | null | 仅群消息有，恒为 `null`（微信无匿名） |
| `wx` | object | **我方扩展字段**，见 4.7 |

> `wx` 是我方额外挂载的原始字段，标准 OneBot 解析器会忽略它，**不影响兼容性**。

### 4.4 引用回复示例

`message` 数组最前面多一个 `reply` 段，`wx.quote_from` 是被引用人的显示名：

```json
{
  "message_id": "49962529981@chatroom_112",
  "user_id": "wxid_1c7w1m1gafnu22",
  "message": [
    {"type": "reply", "data": {"id": "112"}},
    {"type": "text", "data": {"text": "OHOHOH"}}
  ],
  "raw_message": "OHOHOH",
  "wx": {
    "conv_id": "49962529981@chatroom",
    "conv_name": "测试群",
    "type": 1,
    "is_self": false,
    "quote_from": "如鱼得水",

```

> 注意：`reply.data.id` 是**本条消息自己的 `local_id`**，不是被引用消息的 id
> （微信把引用内容拼进了正文，未单独存被引用消息 id）。
> 被引用人的**显示名**在 `wx.quote_from`，原始正文在 `wx.raw`。

---

### 4.5 `message` 消息段

当前只有两种段：

| `type` | `data` | 出现条件 |
|---|---|---|
| `text` | `{"text": "<消息文本>"}` | 文本消息 |
| `reply` | `{"id": "<local_id>"}` | 引用回复，位于数组首位 |

**非文本消息（图片/语音/视频/文件等）当前不做二进制解析**，
统一转成一段 `text`，内容是占位文本，例如 `[图片]`、`[语音]`、`[链接/文件(子类型5)]`。
真实类型看 `wx.type` / `wx.type_name`（见 4.7 与第 6 节）。

如果你需要真实文件内容，请在接收端识别 `wx.type`，我方可以按需扩展。

---

### 4.6 `sender` 发送人

| 字段 | 说明 |
|---|---|
| `user_id` | 发送人 wxid |
| `nickname` | 显示名（群备注优先，其次昵称，最后是 wxid） |
| `card` | 同 `nickname`（微信无独立群名片概念） |
| `role` | 恒为 `"member"`。暂不区分群主 / 管理员 |

---

### 4.7 `wx` 扩展字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `conv_id` | string | 会话原始 id，群为 `<数字>@chatroom`，私聊为对方 wxid |
| `conv_name` | string | 会话显示名（群名 / 对方备注或昵称）；**群改名后旧消息也会用新名字** |
| `sender_name` | string | 发送人显示名，同 `sender.nickname` |
| `type` | int | 微信消息基础类型，见第 6 节 |
| `type_name` | string | 类型中文名，如 `文本`、`图片` |
| `is_self` | bool | **是否本账号自己发的**，见下方重要提示 |
| `quote_from` | string \| null | 被引用人的显示名；非引用回复为 `null` |
| `raw` | string | 微信原始正文（未清洗，最多 2000 字符） |

> ⚠️ **判断"是不是自己发的"，请用 `wx.is_self`，不要比对 `user_id == self_id`。**
> 微信库里同一个账号会同时出现带后缀和不带后缀两种写法，例如
> `self_id = "wxid_1p4nyyjk5ztn19_0e21"`，而自己发消息时 `user_id = "wxid_1p4nyyjk5ztn19"`，
> 字符串不相等。`wx.is_self` 是准确判据。

|---|---|---|
| 1 | 文本 | 完整文本 |
| 3 | 图片 | `[图片]`（占位） |
| 34 | 语音 | `[语音]`（占位） |
| 42 | 名片 | `[名片]`（占位） |
| 43 | 视频 | `[视频]`（占位） |
| 47 | 表情 | `[表情]`（占位） |
| 48 | 位置 | `[位置]`（占位） |
| 49 | 链接/文件(子类型N) | `[链接/文件(子类型N)]`（占位，N 为微信子类型） |
| 50 | 语音通话 | `[语音通话]`（占位） |

（例如 `10000` 系统消息通常不需要 AI 回复）。

## 6. 幂等与去重

**`message_id` = `<conv_id>_<local_id>`，全局唯一且稳定，可直接用作数据库唯一索引。**

我方：同一条消息在消息流里只会出现一次，正常情况不会重复投递。
但**不保证绝对 exactly-once** —— 以下情况可能产生重复：

- 网络超时后重试（我方已收到 2xx 但响应回程丢失）
- `outbox` 积压消息事后重放

**因此请你在接收侧按 `message_id` 做去重**（幂等 upsert），这是唯一可靠的做法。

---

## 7. 顺序性

同一会话内按 `local_id` 递增顺序投递；**跨会话不保证严格时序**。
如果业务强依赖全局时序，请以 `time` 字段排序，并容忍秒级乱序。

---

## 8. 签名（可选）

若配置了签名密钥，每个请求会带：

```
X-WX-Signature: sha256=<hex>
```

算法：**对请求体原始字节**做 HMAC-SHA256，密钥为约定密钥，输出小写 hex。

```python
import hmac, hashlib

# body_bytes = 收到的原始请求体字节（不要 parse 后再 dumps 回来）
expect = "sha256=" + hmac.new(SECRET.encode(), body_bytes, hashlib.sha256).hexdigest()
if not hmac.compare_digest(expect, request.headers["X-WX-Signature"]):
    return 401
```

```javascript
const crypto = require("crypto");

// rawBody = 收到的原始 Buffer（Express 用 express.raw()，或 bodyParser 的 verify 钩子拿）
const expect =
  "sha256=" + crypto.createHmac("sha256", SECRET).update(rawBody).digest("hex");

const got = Buffer.from(req.headers["x-wx-signature"] || "");
const ok =
  got.length === expect.length &&
  crypto.timingSafeEqual(Buffer.from(expect), got);
```

校验要点：

- **必须对收到的原始字节计算**。`JSON.stringify()` 与 Python `json.dumps()`
  的空格规则不同，重新序列化后再算必然对不上（实测两边差一个字节就完全不同）
- 建议用定长时间比较（`hmac.compare_digest` / `crypto.timingSafeEqual`）
- 未配置密钥时不带此头，此时**不应**强制校验
- 中文不做 `\uXXXX` 转义，UTF-8 原样传输

## 9. 我方提供的查询接口（可选）

如果你需要**主动拉取**而不是完全依赖推送，我方本机服务还提供以下接口。

> ⚠️ 服务默认**只监听 `127.0.0.1:18080`**，外网访问不到。
> 要使用这些接口需同机部署，或由你在同机做反向代理。

| 接口 | 说明 |
|---|---|
| `GET /api/health` | 健康检查，含推送统计（已推送 / 失败 / 上次响应码） |
| `GET /api/messages?limit=100` | 最近 N 条；`since_seq=<序号>` 只取增量；`conv=<会话ID>` 只取某会话 |
| `GET /api/state` | 会话列表 + 统计 |
| `GET /api/stream` | SSE 实时流，`event: message`，每帧一个消息对象 |
| `GET /api/export` | 全量 jsonl 下载 |

`/api/messages` 返回结构：

```json
{
  "ok": true,
  "count": 1,
  "messages": [
    {
      "time": "2026-10-27 19:39:06",
      "ts": 1793101146,
      "conv_id": "49159426819@chatroom",
      "conv_name": "改名测试2",
      "sender_id": "wxid_1c7w1m1gafnu22",
      "sender_name": "如鱼得水",
      "type": 1,
      "type_name": "文本",
      "content": "测试消息内容",
      "quote_from": null,
      "raw": "测试消息内容",
      "status": 3,
      "local_id": 9,
      "server_id": 2724830755776726126,
      "is_group": true,
      "self_id": "wxid_1p4nyyjk5ztn19",
      "is_self": false,
      "_seq": 40
    }
  ]
}
```

说明：

- 这里是**我方内部原始记录格式**，不是 OneBot 事件。字段对应关系见第 4 节
- `_seq` 是我方的自增序号，`since_seq` 增量拉取靠它做游标（**保存上次拿到的最大 `_seq`，下次传进来**）
- `limit` 默认 300，上限 2000
- `q` 参数可做关键字过滤（会话名 / 发送人 / 内容）

## 10. 已知限制

1. **非文本消息未解析二进制内容**，只上报占位文本 + 类型（第 5 节）。
2. **`reply` 段的 id 不是被引用消息 id**，见 4.4。
3. **群成员角色不区分**（`role` 恒为 `member`）。
4. **依赖微信客户端在 Mac 上登录并运行**：客户端退出后不再有新消息入库。
5. 消息捕获延迟约 1 秒（受微信自身写库节奏限制，可配置到 0.3 秒轮询）。
6. 群名会随通讯录更新而变化，**同一会话的历史消息在重新拉取时可能显示新名字**。

## 12. 排错对照

| 现象 | 可能原因 |
|---|---|
| 我方报 `Connection refused` | 我方机器残留了失效的 HTTP 代理环境变量，与你的站点无关（已修复：先直连，失败才走代理） |
| 我方显示 `HTTP 404` | 接入地址路径或令牌不对 |
| 我方显示 `HTTP 401/403` | 令牌失效或签名校验失败 |
| 我方显示 `HTTP 400` | 包体解析失败，检查是否按 JSON 对象（非数组）解析 |
| 我方 `failed` 计数增长且 `outbox` 有积压 | 你的站点持续返回 5xx，或响应超过 12 秒 |
| 收到消息但内容为空 | 非文本消息，`raw_message` 为占位文本，看 `wx.type_name` |
