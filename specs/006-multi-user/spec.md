## User Scenarios & Testing *(mandatory)*

### User Story 1 - 注册、登录，拥有自己的空间 (Priority: P1)

一个拿到邀请码的人打开站点：未登录时只看到登录/注册页。凭邀请码注册（用户名+密码）后进入自己的空间——看板、对话、流水、存疑库、设置全部是自己的；退出后回到登录页，未登录状态下别人什么都看不到。

**Why this priority**: 多账户体验的本体；本批次存在的理由。

**Independent Test**: 全新实例建 A/B 两账户，A 单侧走完全部主循环；B 任意界面不可见 A 数据；未登录时前端只有登录页、数据端点全 401。

**Acceptance Scenarios**:

1. **Given** 未登录，**When** 访问任意页面或数据接口，**Then** 只有登录/注册页可达，数据接口一律 401。
2. **Given** 运维命令生成的有效邀请码，**When** 用它 + 用户名 + 密码注册，**Then** 注册成功并进入自己的空空间；该邀请码立即作废（再用即失败）。
3. **Given** 账户 A 与账户 B 各自走完主循环（信源投递→消化→看板→对话），**When** B 浏览任何界面，**Then** 看不到 A 的任何一条原文/事项/流水/对话。

---

### User Story 2 - 信源与 AI 都跟着人走 (Priority: P1)

每个用户有自己的信源接入凭据（token）：把带自己 token 的上游接进 nc 等信源，消息只进自己的库；每个用户配置自己的 LLM key，AI 消化/对话用自己的 key。

**Why this priority**: 没有这一条，多用户只是「多张皮」——数据入口与 AI 消耗必须归属分明。

**Independent Test**: 用 A 的 token 发消息 → 仅 A 的库产生批次、仅 A 的流水可见；B 视图无痕。A 未配 key 时 A 的 AI 提示未配置，不影响 B。

**Acceptance Scenarios**:

1. **Given** A 与 B 各自的信源 token，**When** 以上游身份分别投递消息，**Then** 每条消息只进对应账户，另一账户全链路不可见。
2. **Given** 无 token / 错误 token，**When** 上游继续投递，**Then** 请求被拒绝（沿用现信源契约的失败语义），不落入任何账户。
3. **Given** A 未配 LLM key，**When** A 打开界面，**Then** 与现状一致：界面可用、AI 功能明确提示未配置。
4. **Given** 已登录用户，**When** 打开设置的信源区，**Then** 看到自己的完整接入地址（可复制）；**When** 一键重新生成接入令牌，**Then** 旧地址即刻 401、新地址投递生效。

---

### User Story 3 - 运维命令开门与照看 (Priority: P2)

站内没有管理员角色。开门与照看全部通过运维命令（服务器/本机终端执行）：生成一次性邀请码发给熟人、直接创建账户（首账户/兜底用）、查看用户列表（谁、状态、何时来的）、停用/启用账户、重置密码。

**Why this priority**: 邀请制运营的最小工具；无站内管理面 = 零新增攻击面与测试面；3~5 熟人规模命令行足够。

**Independent Test**: 命令行建首账户 → 发码 → 站内注册成功；命令查列表出现新用户；命令停用后其登录被拒；启用恢复。

**Acceptance Scenarios**:

1. **Given** 运维命令，**When** 生成一个邀请码，**Then** 得到一次性、带有效期的码；重复使用失败。
2. **Given** 已停用账户，**When** 其尝试登录，**Then** 被拒绝并给出明确提示；**When** 运维命令重新启用，**Then** 恢复可登录。
3. **Given** 任意账户状态（含全部账户停用、密码全忘），**When** 执行运维命令，**Then** 管理通道始终可用——永不锁死。

---

### User Story 4 - 安全底线自动兜住 (Priority: P2)

连续猜密码会被限速/锁定；邀请码被枚举会被限速；账户被停用时其会话与信源凭据立即失效。

**Why this priority**: 公网服务的最小安全网（docs/11 阶段 3 安全细则）。

**Independent Test**: 连续失败登录触发锁定；停用后原会话下一请求即 401、信源即刻失效。

**Acceptance Scenarios**:

1. **Given** 同一账户/来源连续多次失败登录，**When** 继续尝试，**Then** 被临时锁定并给出等待提示。
2. **Given** 账户被停用，**When** 其已登录会话发起任何请求，**Then** 立即 401；其信源 token 即刻失效。

---

### Edge Cases

- 邀请码：过期 / 已用 / 不存在 / 猜码枚举 → 明确失败 + 注册限速
- 同名注册 → 拒绝
- 零账户状态：站内只有登录页（注册需要邀请码——此时无码可用，属预期；首账户走运维命令直建）
- 会话过期后的任何操作 → 401 → 前端回登录页
- 存量旧库（data/app.db 或老 zip 用户）：新版不做任何自动处理，是孤岛文件——届时手动搬到对应用户位 / 重录（D5）
- 跨账户猜 URL id（如 /api/items/<别人的 id>）→ 在自己的库里查无此物 → 404。⚠️ 隔离由「每库独立」构造保证，而非逐查询过滤——这正是选址每用户一库的理由（漏过滤=跨用户泄漏，不给自己犯错机会）
- 多用户并发消化：A 的消化失败/超时不影响 B；A 的 key 失效不拖 B 的队列
- 同一浏览器换号：登出 → 登入另一账户 → 各自空间正确
- 运维误停用账户 → 命令再启用即恢复（无不可逆操作）

## Requirements *(mandatory)*

### Functional Requirements

**认证与会话**

- **FR-001**: 未登录状态 MUST 只有登录/注册页可达；所有数据类 API MUST 401（例外：认证端点、信源凭据通道）。
- **FR-002**: 注册 MUST 需有效邀请码 + 唯一用户名 + 密码；邀请码一次性（用后即废）、带有效期；失效/已用码 MUST 明确失败；注册链接 MUST 支持邀请码经 URL 预填（运维直接把链接发给朋友）。
- **FR-003**: 用户名+密码登录后获得会话；登出 MUST 即刻失效。
- **FR-004**: 密码 MUST 以不可逆哈希存储（成熟库，不造密码学）；认证用户可自助改密；运维命令可重置任意账户密码；恢复路径 MUST 不止一条，且命令行侧永远可用。
- **FR-005**: 会话凭据 MUST httpOnly + SameSite + 有过期时间（数值进 Assumptions）。

**隔离**

- **FR-006**: 每账户 MUST 独占一个数据库（`data/users/<uid>.db`）；账户全部数据（原文/事项/元素/版本/证据/对话/设置/信源设置/存疑/流水/已读）归该账户；任何请求路径 MUST 不可能触达他人数据（构造保证，非事后过滤）。
- **FR-007**: 单机使用 MUST 等价于「单账户实例」——全部现有功能行为不变（改造期间单机版全程可用）。

**信源与 AI**

- **FR-008**: 每账户 MUST 拥有自己的信源接入凭据（token，**一账户一把、统一管所有源**）；凭据即定向——投递只进 token 所属账户；无/错 token MUST 拒绝（不落任何库，沿用现信源契约失败语义）；token MUST 明文存储、设置区展示完整接入地址（可复制）、支持**一键轮换**（旧 token 即刻作废）；**日志 MUST 不落 token 明文**（/hook 路径脱敏；反代日志同规——批次 3 落实）。
- **FR-009**: 每账户 MUST 配置自己的 LLM key；AI 功能一律用本人 key；未配置时行为与现状一致（界面可用、明确提示未配置）。

**运维命令（唯一管理通道）**

- **FR-010**: 站内 MUST NOT 存在管理员角色 / 管理页面 / 管理端点；全部管理操作 = 运维命令（服务器/本机终端执行）：创建账户（首账户/兜底用）、生成/作废邀请码（一次性+有效期）、查看用户列表（用户名/状态/创建时间）、停用/启用账户、重置密码。管理通道 MUST 不依赖任何账户状态——永不锁死。

**安全与生命周期**

- **FR-011**: 登录 MUST 有失败限速/锁定（阈值进 Assumptions）。
- **FR-012**: 注册端点 MUST 有限速（防邀请码枚举）。
- **FR-013**: 账户停用 MUST 即刻生效：登录被拒、既有会话下一请求 401、信源凭据即时失效；数据保留（停用为终态——本批不做删除，见 Out of Scope）。
- **FR-014**: 关键认证事件（失败/锁定）与运维命令操作 MUST 有可查记录（以服务器日志为准）。

### Key Entities

- **账户**：用户名（唯一）、密码哈希、状态（可用/停用）、内部 uid（不可由用户名推导）、创建时间。**无管理员标记**——站内不存在管理员实体，管理=运维命令（凭机器访问权）。
- **邀请码**：码、有效期、是否已用、使用者、生成时间。
- **会话**：登录凭据（含过期时间）。
- **账户库**：`data/users/<uid>.db`——现有全部表结构不变（每用户一库 = 隔离由构造保证）。
- **账户登记**：账户与邀请码的系统级登记（独立于各账户库；具体位置 plan 定）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 两账户隔离 E2E——A 走完主循环（信源投递→消化→看板→对话→流水），B 全程看不到 A 的任何一条（以用户所见字段做断言）。
- **SC-002**: 未登录全封锁——未登录状态全部数据端点 401、前端只有登录页（逐端点断言）。
- **SC-003**: 运维闭环 E2E——命令建首账户 → 发码 → 站内注册成号 → 命令列用户可见 → 命令停用后登录被拒/在线会话下一请求即 401 → 命令启用恢复 → 命令重置密码后可正常登录；邀请码一次性/过期拒绝/枚举限速全部生效。
- **SC-004**: 安全底线——失败 N 次锁定生效并按期解锁。
- **SC-005**: 质量门——`npm run check` + `npm run check:dead` + web build 全绿；断言走真实入口（宪法 V）。

## Assumptions

- **管理 = 运维命令**（2026-10-10 Q1/Q2 拍）：凭服务器/本机访问权；站内零管理面；管理通道永不锁死。账户产生的两个入口——站内邀请注册（朋友）/ 运维命令直建（首账户、便携包首启、兜底）——共用同一账户创建核心。
- **迁移三件套不进本批**（D4，已拍）：schema 版本号 / 迁移前自动备份 / 遍历用户库留在批次 2（docs/11 阶段 2 原排期）；本批免费获得「每库各自 ensureSchema」的天然遍历。
- **不做存量数据收编机制**（D5，已拍）：数据量小，届时手动导；旧 `data/app.db` 在新版下是孤岛文件，手动放进对应用户位即可。
- 邀请码即注册闸门（不发码 = 没人能注册）；不设额外全局开关。
- webhook token 方案（2026-10-10 讨论定）：128 位随机 hex、一账户一把；**明文存储**（同库本就有全部业务数据，哈希护小漏大且打断轮换体验——推演见 research R10）；泄露对策 = 一键轮换；日志脱敏（应用本批 + 反代批次 3）。
- 服务器 `.env` 的 `OPENAI_*` 在多用户实例**留空**（自带 key 为方向；留空 = 未配用户得到明确「未配置」提示，而非静默共享运维 key）——单机/便携包不受影响；「托管方提供 AI」属未来付费服务，不在本批（承接 FR-009）。
- 会话 30 天滑动过期；cookie httpOnly + SameSite=Lax + Secure（HTTPS 下）。
- 登录限速默认：同一用户名+来源连续 5 次失败锁 15 分钟（数值 plan 定）；邀请码有效期默认 7 天。
- 密码最小长度 8；用户名 1~20 字符、唯一；用户名不可自助修改。
- 账户内部 uid 随机（库名用 uid，与用户名解耦）。
- 本批不做账户删除（Q3 拍：暂时不考虑）——停用为终态；「人走了怎么办」（删除 + 数据导出）同场议，登记延后项；万一必须删，运维直接操作数据文件兜底（不建功能）。
- 无邮件基础设施：不做「忘记密码」邮件流；重置走运维命令。
- 《简单协议》页、首登引导、robots/noindex 属批次 4；本批注册页不挂未存在的条款链接。
- 术语：对用户叫「账户」；「信源」含义不变（D-88）。

## Out of Scope（本批明确不做）

- 站内管理页面 / 管理员角色 / 管理端点（Q1/Q2 拍：全命令行）
- 账户删除（Q3 拍：暂不考虑；延后项登记；数据导出同场议）
- 存量数据收编/迁移机制（D5 拍：手动导）
- 协作/共享/公开展示/公开注册/计费/跨用户检索（docs/11 阶段 3 红线）
- 数据导出端点（决策⑨缓）
- 二次验证、扫码/OAuth 登录
- 站内 admin 数据浏览（「运维可见」如实写协议，不做工具）
- 用户行为画像/统计
