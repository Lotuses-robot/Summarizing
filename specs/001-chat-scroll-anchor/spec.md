# Feature Specification: 对话面板滚动锚定

**Feature Branch**: `001-chat-scroll-anchor`

**Created**: 2026-10-09

**Status**: Draft

**Input**: User description: "修复对话面板：发送消息和刷新界面后，消息列表应停在底部；用户上翻查看历史时不被打断"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 发送后停在最新消息 (Priority: P1)

用户在前台对话中发送一条消息，消息立即出现在列表末尾。用户无需手动滚动——列表应自动停在最新消息处，让用户马上看到自己的话。

**Why this priority**: 这是对话面板最基本的可用性。发完看不到自己发的、也看不到回复，用户会以为发送失败——直接损害「找不到反馈」的信任。

**Independent Test**: 打开对话面板，滚动到中间位置，发送一条消息，断言列表底部可见刚发送的消息。

**Acceptance Scenarios**:

1. **Given** 对话已有若干条消息且用户停在底部，**When** 用户发送新消息，**Then** 列表停在底部，新消息与随后出现的回复都可见。
2. **Given** 用户发送后正在等待回复（较慢），**When** 回复到达并追加，**Then** 列表仍停在底部，回复可见。

---

### User Story 2 - 刷新后停在底部 (Priority: P1)

用户刷新页面或重新打开对话面板，历史对话被回填。列表应停在最新一条（底部），而不是顶部——用户看到的应是最近发生的事。

**Why this priority**: 与 Story 1 同属「打开就看到最新」的基本预期；停在顶部会让用户每次都要手动滚到底。

**Independent Test**: 有历史对话时刷新页面，打开对话面板，断言列表停在底部（最新一条可见）。

**Acceptance Scenarios**:

1. **Given** 存在历史对话，**When** 用户刷新页面并打开对话面板，**Then** 历史回填后列表停在底部（最新一条可见）。
2. **Given** 历史对话较长（超出可视区），**When** 回填完成，**Then** 停在底部而非顶部。

---

### User Story 3 - 上翻时不被拽回 (Priority: P2)

用户向上滚动，翻看较早的对话。此时若有新消息到达（例如之前的回复延迟返回），不应把用户强行拽回底部——用户正在读的地方应保持不动。

**Why this priority**: 与 P1 相反方向，但同为「滚动尊重用户意图」。缺了它，P1 的「自动停底」会变成「随时抢滚动条」的骚扰。

**Independent Test**: 制造足够多消息使列表可滚动；上翻到中部，触发一条新消息到达，断言视口位置未跳。

**Acceptance Scenarios**:

1. **Given** 用户已上翻离开底部，**When** 新消息到达，**Then** 视口保持原位，用户正在读的内容不跳走。
2. **Given** 用户上翻且已有新消息到达，**When** 用户手动滚回底部，**Then** 恢复「跟随最新」行为。

### Edge Cases

- 消息数量不足以产生滚动条时（内容不超出可视区）：「停在底部」等价于无操作，不得产生异常或空白。
- 正在输入（草稿非空）时收到新消息：草稿与输入焦点不因滚动而丢失。
- 消息列表含空状态的提示文案时，不得被当作「有消息」而触发滚动。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 用户发送消息后，对话列表 MUST 滚动到最新消息可见。
- **FR-002**: 对话面板首次打开 / 页面刷新回填历史后，列表 MUST 停在最新一条（底部）。
- **FR-003**: 新消息到达时，系统 MUST 判断用户是否停留在底部附近：在附近则跟随滚动到最新；已上翻离开则 MUST 保持视口不动。
- **FR-004**: 用户手动滚动回底部后，系统 MUST 恢复「跟随最新」行为。
- **FR-005**: 滚动行为 MUST NOT 影响输入框的草稿内容与焦点。

### Key Entities

无新增数据实体——本特性为既有对话面板的交互行为修正。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 发送消息后，最新消息在 1 秒内进入可视区（无需用户操作）。
- **SC-002**: 刷新后打开对话面板，视口并非停在顶部（最新消息可见）——100% 复现。
- **SC-003**: 用户上翻浏览时收到新消息，视口位移为 0（不被拽回）。
- **SC-004**: 上述行为在自动化测试中覆盖（发送 / 回填 / 上翻三条路径各一断言）。

## Assumptions

- 对话面板为既有功能，本特性只修正其滚动行为，不改变消息的发送、存储或渲染逻辑。
- 消息列表的滚动容器为一致的单一面板（桌面停靠与窄屏浮层共用同一实现）。
- 「底部附近」的判定容差由实现决定，默认取数十字节级别的小容差（用户几乎滚到底即视为「在底部」）。
- 不引入新的消息分组、虚拟滚动或分页——仅行为修正。
